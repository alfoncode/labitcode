## Headings

Headings create the structural hierarchy of your content. We support levels 2–4 within articles (h1 is reserved for the post title).

### Third-Level Heading

Use h3 for subsections within a major topic.

#### Fourth-Level Heading

Use h4 sparingly, for fine-grained breakdowns.

## Inline Text Styles

Regular paragraph text renders at a comfortable reading size with generous line height for readability.

- **Bold text** uses `**double asterisks**`
- *Italic text* uses `*single asterisks*`
- ***Bold and italic*** uses `***triple asterisks***`
- ~~Strikethrough~~ uses `~~double tildes~~`
- Inline `code` uses backticks and renders in a monospaced font with a subtle background

## Code Blocks

Code blocks are one of the most important elements on an engineering blog. Here's how they look across different languages:

### TypeScript

```typescript
interface BlogPost {
  title: string;
  description: string;
  pubDate: Date;
  tags: string[];
  author: 'Alfonso Garcia' | 'AI';
  draft?: boolean;
}

async function getPublishedPosts(): Promise<BlogPost[]> {
  const allPosts = await getCollection('blog');
  return allPosts
    .filter((post) => !post.data.draft)
    .sort((a, b) => b.data.pubDate.valueOf() - a.data.pubDate.valueOf());
}
```

### Python

```python
from dataclasses import dataclass
from datetime import datetime
from typing import Optional

@dataclass
class Project:
    """Represents a project in the lab."""
    name: str
    stack: list[str]
    status: str = "active"
    created_at: datetime = datetime.now()
    repo_url: Optional[str] = None

    def is_active(self) -> bool:
        return self.status == "active"

    def __repr__(self) -> str:
        return f"<Project: {self.name} [{self.status}]>"

# Usage
scanner = Project(
    name="SecureFlow",
    stack=["Python", "Docker", "Redis"],
    repo_url="https://github.com/labitcode/secureflow"
)
print(scanner)  # <Project: SecureFlow [active]>
```

## Mixed Content Flow

Here's how different elements flow together naturally in a real article:

The key insight behind our architecture is that **content sites don't need a JavaScript runtime**. When you analyze what a blog actually does, it's remarkably simple:

1. Render Markdown to HTML
2. Apply consistent styling
3. Generate meta tags for SEO

That's it. Everything else — state management, hydration, virtual DOM diffing — is *overhead* for this use case. Here's how we express this in code:

```typescript
// This is all you need. Really.
const posts = await getCollection('blog');
const sorted = posts
  .filter((p) => !p.data.draft)
  .sort((a, b) => b.data.pubDate.valueOf() - a.data.pubDate.valueOf());
```

> The fastest code is the code that never ships to the browser.

The result? **100/100 Lighthouse scores** across the board, with a `Time to Interactive` measured in milliseconds — not seconds.

## Summary

This style guide covers all the essential Markdown elements you'll use when writing for labitcode:

- **Inline styles**: bold, italic, strikethrough, code, links
- **Block elements**: headings, paragraphs, blockquotes, horizontal rules
- **Code blocks**: multi-language syntax highlighting with copy support
- **Lists**: ordered, unordered, nested, and task lists
- **Tables**: aligned columns with clean styling
- **Images**: rounded corners, centered layout

Every element is designed for optimal readability in both **light** and **dark** modes, ensuring a premium reading experience regardless of preference.
